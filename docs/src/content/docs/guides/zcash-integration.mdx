TCSwap provides comprehensive support for Zcash through the UTXO toolbox with specialized handling for Zcash transparent addresses. This guide covers everything you need to know about working with Zcash in your applications.

## Overview

The Zcash integration in TCSwap supports:

- **Transparent addresses only** (t1... P2PKH and t3... P2SH; TEX `tex1...` recipients are paid via their transparent equivalent)
- **Custom address generation** with 2-byte prefixes
- **PSBT-based transaction building** for compatibility
- **Full UTXO management** and fee estimation
- **Memo support** via OP_RETURN outputs
- **@bitgo/utxo-lib** for Zcash PSBTs (NU6.1 transaction version) and key handling

## Key Features

### Transparent Address Support

TCSwap supports Zcash transparent addresses which provide Bitcoin-like functionality on the Zcash network:

```ts twoslash
import { Chain, getUtxoToolbox } from "@tcswap/sdk";

async function validateZcashAddresses() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash);

  const mainnetValid = zcashToolbox.validateAddress(
    "t1XVXWCvpMgBvUaed4XDqWtgQgJSu1Ghz7F"
  );
  console.log("Mainnet address valid:", mainnetValid);

  const p2shValid = zcashToolbox.validateAddress(
    "t3Vz22vK5z2LcKEdg16Yv4FFneEL1zg9ojd"
  );
  console.log("P2SH address valid:", p2shValid);

  const shieldedValid = zcashToolbox.validateAddress(
    "zs1z7rejlpsa98s2rrrfkwmaxu2xldqmfq5nj2m3hq6s7r8qjq8eqqqq9p4e7x"
  );
  console.log("Shielded address valid:", shieldedValid);

  return { mainnetValid, p2shValid, shieldedValid };
}
```

### Custom Address Generation

Zcash uses 2-byte version prefixes for addresses, which requires custom generation logic:

```ts twoslash
import { Chain, getUtxoToolbox } from "@tcswap/sdk";

async function generateZcashAddress() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
    phrase:
      "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about",
  });

  const address = await zcashToolbox.getAddress();
  console.log("Generated address:", address);

  const secondAccountToolbox = await getUtxoToolbox(Chain.Zcash, {
    phrase:
      "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about",
    index: 1,
  });

  const customAddress = await secondAccountToolbox.getAddress();
  console.log("Index 1 address:", customAddress);

  return { address, customAddress };
}
```

## Transaction Operations

### Basic Transfer

```ts twoslash
import { AssetValue, Chain, FeeOption, getUtxoToolbox } from "@tcswap/sdk";

async function sendZcash() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
    phrase: "your twelve word mnemonic phrase here",
  });

  const amount = AssetValue.from({
    chain: Chain.Zcash,
    value: "0.001",
  });

  const txHash = await zcashToolbox.transfer({
    recipient: "t1XVXWCvpMgBvUaed4XDqWtgQgJSu1Ghz7F",
    assetValue: amount,
    feeOptionKey: FeeOption.Fast,
    memo: "Payment for services",
  });

  console.log("Transaction sent:", txHash);
  return txHash;
}
```

### Manual Transaction Building

For advanced use cases, you can build transactions manually:

```ts twoslash
import { AssetValue, Chain, getUtxoToolbox } from "@tcswap/sdk";

async function buildZcashTransaction() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
    phrase: "your twelve word mnemonic phrase here",
  });

  const senderAddress = await zcashToolbox.getAddress();

  const feeRates = await zcashToolbox.getFeeRates();

  const { psbt, inputs, outputs } = await zcashToolbox.createTransaction({
    recipient: "t1XVXWCvpMgBvUaed4XDqWtgQgJSu1Ghz7F",
    assetValue: AssetValue.from({ chain: Chain.Zcash, value: "0.002" }),
    sender: senderAddress,
    feeRate: feeRates.fast,
    memo: "Manual transaction",
  });

  console.log("PSBT created with", inputs.length, "inputs");
  console.log("Outputs:", outputs.length);

  return { psbt, inputs, outputs };
}
```

## Network Configuration

### Address Prefix

Zcash support targets mainnet. When deriving from a phrase, the toolbox encodes the address with the mainnet `t1` prefix; with `envs.isStagenet` enabled it uses the testnet prefix (`tm...`) instead. Balances, UTXOs and broadcasting always go through the mainnet UTXO data provider.

```ts twoslash
import { Chain, USwapConfig, getUtxoToolbox } from "@tcswap/sdk";

USwapConfig.setApiKey("blockchair", "your-blockchair-api-key");

const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
  phrase: "your mnemonic here",
});

const address = await zcashToolbox.getAddress();
console.log("Mainnet address:", address);
```

## Error Handling and Best Practices

### Common Error Patterns

```ts twoslash
import { AssetValue, Chain, USwapError, getUtxoToolbox } from "@tcswap/sdk";

async function handleZcashErrors() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
    phrase: "your mnemonic here",
  });

  try {
    const txHash = await zcashToolbox.transfer({
      recipient: "t1XVXWCvpMgBvUaed4XDqWtgQgJSu1Ghz7F",
      assetValue: AssetValue.from({ chain: Chain.Zcash, value: "1000" }),
    });

    return txHash;
  } catch (error) {
    if (error instanceof USwapError) {
      switch (error.message.split(":")[0]) {
        case "toolbox_utxo_insufficient_balance":
          console.error("Insufficient balance for transaction");
          break;
        case "toolbox_utxo_invalid_address":
          console.error("Invalid recipient address");
          break;
        case "toolbox_utxo_broadcast_failed":
          console.error("Failed to broadcast transaction");
          break;
        default:
          console.error("USwap error:", error.message);
      }
    } else {
      console.error("Unexpected error:", error);
    }
    throw error;
  }
}
```

### Validation Best Practices

```ts twoslash
import { Chain, getUtxoToolbox } from "@tcswap/sdk";

async function validateInputs() {
  const zcashToolbox = await getUtxoToolbox(Chain.Zcash);

  function isValidZcashAddress(address: string): boolean {
    const isValid = zcashToolbox.validateAddress(address);

    if (!isValid) {
      console.warn(`Invalid Zcash address: ${address}`);
      return false;
    }

    const isTransparent = address.startsWith("t1") || address.startsWith("t3");
    const isTex = address.toLowerCase().startsWith("tex1");

    if (!(isTransparent || isTex)) {
      console.warn(`Unsupported address format: ${address}`);
      return false;
    }

    return true;
  }

  const recipientAddress = "t1XVXWCvpMgBvUaed4XDqWtgQgJSu1Ghz7F";

  if (!isValidZcashAddress(recipientAddress)) {
    throw new Error("Invalid recipient address");
  }

  return { valid: true };
}
```

## Limitations and Considerations

### Current Limitations

1. **Transparent Addresses Only**: TCSwap does not support Zcash shielded addresses (z-addresses)
2. **No Sapling/Orchard**: Only transparent pool transactions are supported
3. **Standard UTXO Model**: Uses Bitcoin-like UTXO management without privacy features
4. **Network Fees**: Uses Zcash network fee estimation

### Performance Considerations

```ts twoslash

  const zcashToolbox = await getUtxoToolbox(Chain.Zcash);
```

## Migration from Previous Versions

### Architecture Updates

TCSwap has evolved to use modern cryptographic libraries for Zcash operations:

- **Current**: Uses `@bitgo/utxo-lib` (Zcash PSBTs and ECPair) with `@scure/bip32`/`@scure/bip39` for key derivation
- **Impact**: No breaking changes to public API, improved performance and bundle size

### API Compatibility

All existing Zcash integration code continues to work without changes:

```ts twoslash
import { Chain, getUtxoToolbox } from "@tcswap/sdk";

const zcashToolbox = await getUtxoToolbox(Chain.Zcash, {
  phrase: "your mnemonic here",
});

const address = await zcashToolbox.getAddress();
const balances = await zcashToolbox.getBalance(address);
```

The architecture updates are transparent to users and provide:

- Reduced bundle size
- Better maintenance and security
- Improved consistency with other UTXO chains
- Reliable fee estimation
